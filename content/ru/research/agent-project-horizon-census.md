Автономный агент собрал двенадцать продуктов, большую часть за три месяца. В них 509 тысяч строк кода, 3 143 критерия приёмки, из них 2 368 отмечены доказанными. Из 2 057 коммитов 1 497 сделал агент, это 73%.

Мы хотели измерить на этом корпусе ложный успех: сколько «доказанного» на самом деле не проверено и можно ли это предсказать по тому, как агент работал. Для второго вопроса нужен журнал: какая правка ради какого критерия. Оказалось, что для 42% правок восстановить это нельзя.

## Что такое корпус

Продукты собраны на одном шаблоне: Bun, Elysia, PostgreSQL, Drizzle. Спецификация каждого разбита на use case'ы, у каждого критерии приёмки (AC) с уровнем проверки: unit, integration, browser. Код живёт слайсами: слайс это вертикальный кусок продукта со своим каталогом кода и своими AC. Галочку «доказано» ставит раннер по junit-отчёту, если находит зелёный тест с ID критерия в имени.

Перепись (K0) шла только по чтению: `git log`, `git show`, `ls-files` в каждом репозитории, без checkout. В выходе одни агрегаты, ни кода, ни текстов сообщений. Прогон около 15 секунд.

| | всего |
|---|---|
| продуктов | 12 |
| AC / доказано | 3 143 / 2 368 (75%) |
| слайсов | 133 |
| коммитов (агент / прочие) | 2 057 (1 497 / 560) |
| строк в `src` (код / тесты) | 508 917 (392 тыс. / 117 тыс.) |
| AC, когда-либо доказанных | 2 574 |
| из них теряли доказательство | 57 (2,2%) |

Доля доказанных сильно разная: от 23% у самого большого продукта (682 AC) до 98–100% у пяти других. Почти все недоказанные AC без единого теста: 765 из 775. Статуса «тест красный» сейчас нет ни у одного критерия.

Агентским я считал коммит с трейлером `Co-Authored-By: …Claude`. Всё прочее записано в «человека», включая merge-коммиты, так что 560 это оценка сверху.

## Регрессий по галочкам почти нет

Из 2 574 AC, доказанных хотя бы раз, галочку теряли 57. Почти все переходы с причиной «теста нет»: тест удалили или переименовали. Переход «тест падает» нашёлся у одного критерия.

Отчасти это хорошая новость. Но [параллельный замер (K1)](/ru/research/agent-green-tests-that-catch-no-mutants) показал, что у 16% доказанных AC связанный тест не ловит ни одной мутации кода. Тест, который ничего не проверяет, и не покраснеет. Поэтому низкая доля регрессий говорит в первую очередь о том, что раннер не видит падений.

## Единица анализа не та, что в плане

План требовал не меньше 2 000 слайсов, чтобы учить предсказатель ложного успеха. Слайсов 133, за всю историю 137. Даже коммитов всего 2 057. Порог был рассчитан на «прогон слайса», а в этих продуктах слайс это модуль размером с use case, его не прогоняют сотни раз.

Единицей анализа становится критерий приёмки: 3 143, из них 2 574 доказывались. Пар «агентский коммит × слайс» 742, это можно использовать как заменитель эпизода.

## Транскрипты: что сохранилось

Claude Code сам удаляет старые транскрипты сессий (настройка `cleanupPeriodDays`). К моменту переписи в каталогах проектов лежали сессии с 12.10.2026; у трёх продуктов транскриптов не осталось совсем. Часть истории с 27.08 нашлась в архивной копии домашнего каталога. Всего для K2 набралось 375 основных сессий за 27.08–27.10.2026 по 11 продуктам.

Вывод для всех, кто собирается изучать своего агента: `cleanupPeriodDays` в настройках Claude Code надо поднять до того, как история понадобится. Мы скопировали транскрипты в архив (2,1 ГБ) уже после того, как часть истории пропала.

Из 11 229 вызовов инструментов в сохранившихся сессиях 86% приходится на Bash. Агент правит файлы через `sed`, heredoc и скрипты чаще, чем через встроенный редактор, и это главная трудность для парсера.

## K2: парсер журнала

Парсер вытаскивает из транскриптов события: правку файла, прогон тестов и его исход, коммит, вызовы проверок. Для правок через Bash он разбирает дифф, команду VCS или эвристику по команде. В выход идут только пути, типы, ID критериев, хеши и время.

375 сессий дали 17 374 события, из них 12 025 правок; 6 499 правок `src` и тестов внутри продуктов. Каждую правку надо привязать к слайсу, а лучше к критерию.

| уровень привязки | доля правок src/test |
|---|---|
| строгая: путь слайса или ID критерия в правке | 49,0% |
| + через коммит, в который правка вошла | **57,8%** |
| + «между двумя правками одного слайса» | 71,1% |
| + любой уникальный контекст | 78,7% |
| к конкретному AC (строго) | 26,8% |

Порог был 80% однозначной привязки. Строгая привязка вместе с коммитом даёт 57,8%, Выборку из 30 событий сверили с исходным транскриптом; сверял Claude, а не человек. В ней 16 событий со строгой привязкой или привязкой через коммит, все 16 привязаны к слайсу верно, а у 10 из них, где был назван критерий, верен и он. Ещё 6 событий привязаны только по контексту, из них 3 неверно, поэтому контекстные уровни (до 78,7%) в анализ не идут. Остальные 8 парсер честно оставил без привязки.

Половина непривязанного приходится на общую обвязку шаблона: шлюз, веб-приложение, модуль идентификации. Эти правки ни к какому одному слайсу не относятся по сути, и честная привязка для них «никуда».

## Что можно посчитать уже сейчас

На строго привязанных событиях часть формул процедуры уже вычислима. Это черновые счётчики: точность самих формул ещё не проверялась, а красный прогон виден только если агент запускал тесты через Bash и в выводе нашлись упавшие слайсы.

| формула | случаев | нарушений |
|---|---|---|
| коммит без зелёного прогона после последней правки | 760 | 260 (34%) |
| правка `src` слайса без красного теста этого слайса раньше в сессии | 2 329 | 1 266 (54%) |
| переход красный → зелёный, между которыми правились только тесты | 551 | 125 (23%) |
| проверка приёмки без интеграционного или e2e-прогона после правки | 43 | 40 |

Третья строка интереснее всего. Тест упал, агент правит тест, тест зелёный, код не тронут. Иногда это законно: тест был неверный. Но это ровно тот путь, которым появляется тест, который ничего не проверяет. Следующий шаг (K3): связать эту формулу с пустыми зелёными из K1. Из двенадцати формул плана на уровне слайса вычислимы около семи; формулам на уровне критерия нужны новые транскрипты, где агент явно вызывает проверку приёмки.

## Границы

- Корпус один: один агент, один шаблон. Перенос на другие стеки не проверялся.
- «Агентский коммит» определён по трейлеру; коммиты агента без трейлера попали в «человека».
- Транскрипты покрывают два месяца из трёх и не все продукты. Сессии субагентов в K2 не разбирались.
- Формулы процедуры посчитаны на 58% правок с надёжной привязкой. Если непривязанные 42% устроены иначе (например, правки обвязки делаются без тестов чаще), оценки смещены.
- Корпус живой: в продуктах продолжают работать сессии, повторный прогон даёт немного другие числа. Снимок от 27.10.2026.

Галочек у агента много, и они почти не откатываются. Но что он делал ради каждой из них, по его же журналу можно сказать только для шести правок из десяти.
